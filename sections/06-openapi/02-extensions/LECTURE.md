# VS Code 拡張機能と lint

![06 章 VS Code 拡張機能と lint](./images/00-thumbnail.svg)

`openapi.yaml` は長く、字下げや `$ref` の書き間違いに気づきにくいファイルです。この節では、書くのを助けてくれる VS Code の拡張機能を入れ、決まりどおりに書けているかをコマンド（**Redocly CLI** の lint）でも確かめられるようにします。

## 使う拡張機能

| 拡張機能 | ID | できること |
|---|---|---|
| OpenAPI (Swagger) Editor | `42Crunch.vscode-openapi` | 入力の補完、OpenAPI explorer（パスや部品の一覧）、`$ref` の参照先へ移動、Swagger UI / ReDoc でのプレビュー |
| Redocly OpenAPI | `Redocly.openapi-vs-code` | `redocly.yaml` の決まりで間違いを表示、参照先ののぞき見 |
| YAML | `redhat.vscode-yaml` | YAML の字下げや書き方の間違いを表示 |

### プロジェクトで勧める

`.vscode/extensions.json` に拡張機能の ID を書いておくと、このフォルダを VS Code で開いた人に「入れておくとよい拡張機能」として表示されます。チームで同じ道具をそろえるのに便利です。

::diff{file="api/.vscode/extensions.json"}

`nest new` が作った `.gitignore` は `.vscode/` の中を Git に入れない設定ですが、`extensions.json` だけは入れるように書かれています（`!.vscode/extensions.json`）。

`api/` を VS Code で開くと、右下に「このワークスペースには拡張機能の推奨事項があります」と出るので、**インストール** を押します。拡張機能のビューで `@recommended` と検索しても一覧が出ます。

:::warning
VS Code では `api/` を開いてください（`handson/` や `api/src/` ではなく）。`.vscode/` と、後で作る `redocly.yaml` は、開いたフォルダの直下にあるときに読まれます。
:::

## 拡張機能を使ってみる

`openapi.yaml` を開いて、次を試してみてください。

- **OpenAPI explorer** … 左のアクティビティバーの OpenAPI のアイコンを押すと、パス・操作・`components` の一覧が出ます。押すと、その場所へ移動します
- **補完** … 新しい行で `req` と打つと `requestBody` が候補に出ます。何を書けるかが分かります
- **参照先へ移動** … `$ref: '#/components/schemas/Note'` を Cmd（Windows・Linux は Ctrl）を押しながらクリックすると、`Note` の定義へ移動します
- **プレビュー** … エディタの右上のプレビューのボタンを押すと、API のドキュメントの画面が横に出ます。書いた説明がどう見えるかを確かめられます

わざと間違えてみると、拡張機能の働きがよく分かります。たとえば `'#/components/schemas/Note'` を `'#/components/schemas/Notes'` に変えると、参照先が無いことが赤い波線で示されます。

## Redocly CLI を入れる

エディタで見るだけでなく、コマンドでも確かめられるようにしておきます。コマンドなら、レビューの前や CI で、決まりどおりかを機械的に確かめられます。

```bash
npm install -D @redocly/cli
```

`package.json` の `scripts` に、`openapi.yaml` を確かめるコマンドを足します。`devDependencies` の行は、`npm install -D` が足したものです。

::diff{file="api/package.json"}

まだ `redocly.yaml` を作らずに、実行してみます。

```bash
npm run lint:api
```

```text
No configurations were provided -- using built in recommended configuration by default.

validating openapi.yaml...
[1] openapi.yaml:14:5 at #/paths/~1notes/get

Every operation should have security defined on it or on the root level.

12 | paths:
13 |   /notes:
14 |     get:
   |     ^^^
15 |       tags: [notes]
16 |       operationId: listNotes

Error was generated by the security-defined rule.
...

❌ Validation failed with 5 errors and 3 warnings.
```

問題ごとに、場所（`openapi.yaml:14:5`）・説明・どの決まり（`security-defined` など）で見つかったかが出ます。出てくる決まりは次の 4 つです。

- `security-defined`（エラー、5 か所）… 操作に認証（`security`）が書かれていない
- `info-license`（警告）… `info` にライセンスが無い
- `no-server-example.com`（警告）… `servers` が `localhost` を指している
- `operation-4xx-response`（警告）… `GET /notes` に `4xx` の応答が無い

Redocly は、OpenAPI として正しいかに加えて、このような **書き方の決まり（ルール）** でも確かめます。何も設定しないと、おすすめの決まり（`recommended`）がすべて使われます。

## 決まりを redocly.yaml に書く

どの決まりを使うかを `redocly.yaml` に書きます。拡張機能も CLI も、このファイルを読みます。

::diff{file="api/redocly.yaml"}

- `extends: [recommended]` … Redocly のおすすめの決まりを使います
- `rules` … このプロジェクトに合わない決まりを切ります

| 決まり | 切る理由 |
|---|---|
| `info-license` | 公開しない API なので、ライセンスは書かない |
| `no-server-example.com` | 手元で動かす API なので、`servers` が `localhost` でよい |
| `security-defined` | このハンズオンの API には認証を付けない |
| `operation-4xx-response` | 一覧（`GET /notes`）は、`4xx` を返すことが無い |

もう一度実行します。

```bash
npm run lint:api
```

```text
validating openapi.yaml...
openapi.yaml: validated in 10ms

Woohoo! Your API description is valid. 🎉
```

:::notice
決まりを切るのは、理由を説明できるときだけにします。たとえば認証のある API なら、`security-defined` は切らずに、`openapi.yaml` に `security` を書きます。
:::

:::faq

### 推奨の拡張機能の表示が出てこない

`api/` ではなく、その上のフォルダや `api/src/` を開いていないか確かめてください。表示を一度閉じた場合は、拡張機能のビューで `@recommended` と検索すると出てきます。

### 42Crunch の拡張機能で「Audit」や「Scan」を勧められる

42Crunch の拡張機能には、API のセキュリティを調べる機能（サインインが必要）もあります。このハンズオンでは、編集とプレビューの機能だけを使います。

### Redocly の拡張機能が間違いを表示しない

`redocly.yaml` が、VS Code で開いたフォルダの直下にあるか確かめてください。拡張機能は、ワークスペースの直下の `redocly.yaml` を読みます。

:::
